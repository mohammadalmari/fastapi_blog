# API overview

Every route the app serves, what it needs, and what it is for.

This page is a map, not the reference. The full reference is generated by
FastAPI from the code, so it cannot go out of date:

- `/docs`: interactive; its "Authorize" button logs you in
- `/redoc`: the same as a readable document
- `/openapi.json`: the schema, for generating clients

Every response carries `X-Request-ID`: quote it when reporting a problem.
Some routes are [rate limited](concepts/rate-limiting.md) and answer 429 with
a `Retry-After` header when used too often.

Request and response shapes, field rules and error codes are there. All three
are served in debug mode only.

## Conventions

- Feature routes are under `/api/v1`. `/health` is not: load balancers and
  monitors hardcode it, so it must not move when the API version does.
- Authenticate with `Authorization: Bearer <access token>`.
- Errors are `{"detail": "..."}`. Validation errors (422) carry a list, each
  item with `type`, `loc` and `msg`.
- 401 means not logged in, 403 means logged in but not allowed, 409 means the
  request clashes with what exists.
- Ids are 24-character hex strings. A malformed one is a 422, an unknown one
  a 404. A 404 is also the answer for something the caller may not know
  exists, such as someone else's draft.

## Accounts and sessions

See [concepts/authentication.md](concepts/authentication.md).

| Route | Needs | What it does |
| ----- | ----- | ------------ |
| `POST /api/v1/auth/register` | Nothing | Create an account (JSON: `email`, `username`, `password`) |
| `POST /api/v1/auth/login` | Nothing | Log in with an email or username (form: `username`, `password`); sets the refresh cookie |
| `POST /api/v1/auth/refresh` | Refresh cookie | A new access token, and a new refresh token in the cookie |
| `POST /api/v1/auth/logout` | Refresh cookie | End this session |
| `POST /api/v1/auth/logout-all` | Login | End every session of the caller |

## Users

| Route | Needs | What it does |
| ----- | ----- | ------------ |
| `GET /api/v1/users/me` | Login | The caller's account, roles and effective permissions |
| `PATCH /api/v1/users/me` | Login | Change your username, display name or bio; an empty string clears the last two |
| `POST /api/v1/users/me/password` | Login, and the current password | Change your password; ends every session |
| `PUT /api/v1/users/me/avatar` | Login | Upload an avatar (form field `file`; PNG, JPEG or WebP, at most 2 MB) |
| `DELETE /api/v1/users/me/avatar` | Login | Remove your avatar |
| `GET /api/v1/users` | `users:read:any` | Every account with its roles, newest first; `is_active` filters |
| `GET /api/v1/users/{username}` | Nothing | A public profile; a deactivated account has none |
| `PATCH /api/v1/users/{user_id}/status` | `users:deactivate`, and every permission the account holds | Deactivate an account or bring it back (JSON: `is_active`) |
| `PUT /api/v1/users/{user_id}/roles` | `users:assign_roles` | Replace a user's roles |
| `GET /media/avatars/{avatar_key}` | Nothing | An avatar's picture, as addressed by `avatar_url`. Not under `/api/v1` |

## Posts

See [features/posts.md](features/posts.md).

| Route | Needs | What it does |
| ----- | ----- | ------------ |
| `GET /api/v1/posts` | Nothing; with a login, `liked_by_me` is yours. A bad token is a 401 | Published posts, newest first; `tag`, `author`, `limit` and `cursor` as query parameters |
| `POST /api/v1/posts` | `posts:create` | Write a post; it starts as a draft |
| `GET /api/v1/posts/{slug}` | Nothing for a published post | One post. A draft is shown to its author and to holders of any `posts:...:any` permission |
| `PATCH /api/v1/posts/{post_id}` | `posts:update:own` on your post, or `posts:update:any`; for a published post also the permission to publish it | Edit a post |
| `DELETE /api/v1/posts/{post_id}` | `posts:delete:own` on your post, or `posts:delete:any` | Delete a post, its comments and the likes on them |
| `POST /api/v1/posts/{post_id}/publish` | `posts:publish:own` on your post, or `posts:publish:any` | Make a post public |
| `POST /api/v1/posts/{post_id}/unpublish` | `posts:publish:own` on your post, or `posts:publish:any` | Turn it back into a draft |
| `GET /api/v1/users/me/posts` | Login | The caller's own posts, drafts included; `status` filters |
| `GET /api/v1/tags` | Nothing | The 100 most used tags on published posts, with their counts; may be up to two minutes behind |

Lists are paged by cursor: pass the `next_cursor` of one page as `cursor` to
get the next, until it is null. A cursor belongs to the list that issued it.
A query parameter a list doesn't have is a 422, not ignored.

## Comments

See [features/comments.md](features/comments.md). A comment is as visible as
the post it is on.

| Route | Needs | What it does |
| ----- | ----- | ------------ |
| `GET /api/v1/posts/{post_id}/comments` | Nothing, if the post is visible | The comments on a post, oldest first, each with its number of replies |
| `POST /api/v1/posts/{post_id}/comments` | `comments:create` | Comment on a published post |
| `GET /api/v1/comments/{comment_id}/replies` | Nothing, if the post is visible | The replies to a comment, oldest first |
| `POST /api/v1/comments/{comment_id}/replies` | `comments:create` | Reply to a comment; replies can't be replied to |
| `PATCH /api/v1/comments/{comment_id}` | `comments:update:own`, on your own comment | Edit your comment |
| `DELETE /api/v1/comments/{comment_id}` | `comments:delete:own` on your comment, or `comments:delete:any` | Delete a comment; if it has replies it stays as a placeholder with its content erased. Its likes go either way |

## Likes

See [features/likes.md](features/likes.md). Each route answers 204 with no
body, and sending one twice ends where sending it once does. Taking a like
back answers 204 for any id, so it says nothing about the post or comment.

| Route | Needs | What it does |
| ----- | ----- | ------------ |
| `PUT /api/v1/posts/{post_id}/like` | `likes:create`, and a post you can see | Like a post |
| `DELETE /api/v1/posts/{post_id}/like` | Login | Take your like back |
| `PUT /api/v1/comments/{comment_id}/like` | `likes:create`, and a comment you can see | Like a comment |
| `DELETE /api/v1/comments/{comment_id}/like` | Login | Take your like back |

## Roles and permissions

See [concepts/roles-and-permissions.md](concepts/roles-and-permissions.md).

| Route | Needs | What it does |
| ----- | ----- | ------------ |
| `GET /api/v1/permissions` | `roles:read` | Every permission that exists |
| `GET /api/v1/roles` | `roles:read` | All roles, by name |
| `POST /api/v1/roles` | `roles:create` | Create a role |
| `GET /api/v1/roles/{role_id}` | `roles:read` | One role |
| `PATCH /api/v1/roles/{role_id}` | `roles:update` | Edit a role; `is_default: true` makes it the role new accounts get |
| `DELETE /api/v1/roles/{role_id}` | `roles:delete` | Delete a role and take it from its holders |

Creating, editing and assigning roles are also limited to permissions the
caller holds.

## Trying it

```bash
# Log in; the refresh cookie is saved to the jar
curl -c jar.txt -d 'username=you@example.com&password=...' \
  http://127.0.0.1:8000/api/v1/auth/login

# Use the access token from the response
curl -H 'Authorization: Bearer <access token>' http://127.0.0.1:8000/api/v1/users/me

# Trade the refresh cookie for a new access token
curl -b jar.txt -c jar.txt -X POST http://127.0.0.1:8000/api/v1/auth/refresh
```
