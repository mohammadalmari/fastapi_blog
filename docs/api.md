# API overview

Every route the app serves, what it needs, and what it is for.

This page is a map, not the reference. The full reference is generated by
FastAPI from the code, so it cannot go out of date:

- `/docs`: interactive; its "Authorize" button logs you in
- `/redoc`: the same as a readable document
- `/openapi.json`: the schema, for generating clients

Request and response shapes, field rules and error codes are there. All three
are served in debug mode only.

## Conventions

- Feature routes are under `/api/v1`. `/health` is not: load balancers and
  monitors hardcode it, so it must not move when the API version does.
- Authenticate with `Authorization: Bearer <access token>`.
- Errors are `{"detail": "..."}`. Validation errors (422) carry a list, each
  item with `type`, `loc` and `msg`.
- 401 means not logged in, 403 means logged in but not allowed, 409 means the
  request clashes with what exists.
- Ids are 24-character hex strings. A malformed one is a 422, an unknown one
  a 404.

## Accounts and sessions

See [concepts/authentication.md](concepts/authentication.md).

| Route | Needs | What it does |
| ----- | ----- | ------------ |
| `POST /api/v1/auth/register` | Nothing | Create an account (JSON: `email`, `username`, `password`) |
| `POST /api/v1/auth/login` | Nothing | Log in with an email or username (form: `username`, `password`); sets the refresh cookie |
| `POST /api/v1/auth/refresh` | Refresh cookie | A new access token, and a new refresh token in the cookie |
| `POST /api/v1/auth/logout` | Refresh cookie | End this session |
| `POST /api/v1/auth/logout-all` | Login | End every session of the caller |

## Users

| Route | Needs | What it does |
| ----- | ----- | ------------ |
| `GET /api/v1/users/me` | Login | The caller's account, roles and effective permissions |
| `PUT /api/v1/users/{user_id}/roles` | `users:assign_roles` | Replace a user's roles |

## Roles and permissions

See [concepts/roles-and-permissions.md](concepts/roles-and-permissions.md).

| Route | Needs | What it does |
| ----- | ----- | ------------ |
| `GET /api/v1/permissions` | `roles:read` | Every permission that exists |
| `GET /api/v1/roles` | `roles:read` | All roles, by name |
| `POST /api/v1/roles` | `roles:create` | Create a role |
| `GET /api/v1/roles/{role_id}` | `roles:read` | One role |
| `PATCH /api/v1/roles/{role_id}` | `roles:update` | Edit a role; `is_default: true` makes it the role new accounts get |
| `DELETE /api/v1/roles/{role_id}` | `roles:delete` | Delete a role and take it from its holders |

Creating, editing and assigning roles are also limited to permissions the
caller holds.

## Trying it

```bash
# Log in; the refresh cookie is saved to the jar
curl -c jar.txt -d 'username=you@example.com&password=...' \
  http://127.0.0.1:8000/api/v1/auth/login

# Use the access token from the response
curl -H 'Authorization: Bearer <access token>' http://127.0.0.1:8000/api/v1/users/me

# Trade the refresh cookie for a new access token
curl -b jar.txt -c jar.txt -X POST http://127.0.0.1:8000/api/v1/auth/refresh
```
